# SPEC · 小说 Harness 平台

> 对齐产物（2026-10-13）：单机自用 / 中文网文长篇 / 长篇优先单卷走通 / 固定流水线 / 双层 git / 规则装配 / Rig 接模型。
> 调研依据：[ai写小说技术方案 · 调研报告](../research/ai写小说技术方案-2026-10-13/REPORT.md)

## 问题

中文网文长篇作者（首先是自己）用通用大模型写百万字长篇，绕不开三座大山：**一致性崩塌**（20-40 万字开始吃书、人设漂移、伏笔被提前说破）、**流程失控**（没有上位约束，越写越偏直至烂尾）、**成本失控**（上下文乱喂，token 烧钱但不解决问题）。现有方案没有趁手的：马良写作是闭源订阅产品、流程约束最全但不可自持；DeepWrite 开源但缺网文向的流程与一致性深度；裸用 CLI agent 没有作品管理。做一个本地优先的 Harness 工作台：**固定流水线保证"不烂尾"，一致性工程（账本 + 规则装配 + 审校）保证"不吃书"，diff 审阅保证"AI 永远不静默改稿"。**

## 走通路径

新建作品 → 录设定（人物/世界观/悬念，含可见性）→ 生成并确认总纲 → 拆一卷卷纲 → 滚动生成章纲 → 逐章正文（规则装配上下文 → agent 生成 → diff 审阅落盘 → 账本自动回写）→ 审校（一致性检查 + 去 AI 味）→ 修复收敛。

**MVP 交付判据：一卷 3~5 章从新建到审校通过全程可演示，期间任意一步可从 git 历史回溯。**

## 核心机制

1. **主流程状态机**：设定 → 总纲 → 卷纲 → 章纲 → 正文 → 审校。每阶段定义进入条件（上游产物已确认）与退出产物；门不满足则拦截推进。卷纲先行、章纲随正文滚动生成，不一次锁死（长篇"边写边长"，来源：马良方法论）。
2. **自由旁路**：任何阶段可开旁路会话（自动绑定当前作品上下文），处理流程外问题——设定推演、矛盾排查、头脑风暴。旁路产物要进正稿或设定库，必须走 diff 审阅回流。
3. **git 双层**：作品目录 = git 仓库，章节、设定、账本都是 md 文件 + frontmatter。agent 修改统一走 patch → diff 视图 → 接受（自动 commit）/ 拒绝（丢弃）。git 实现用命令行 git 或 git2-rs，骨架期定并记 DECISIONS。
4. **连续性账本**：结构化 md，记录角色当前状态（位置/等级/关系/持有物）、已交代事实、伏笔登记。完稿一章后 agent 从正文提取状态变更，提议 diff 回写账本；下一章装配时注入账本摘要。账本不受上下文窗口限制，是"记忆缺锚"的解。
5. **规则装配**：正文阶段默认装配 = 系统提示词（人设/文风指令，置于最前）+ 本卷卷纲 + 本章章纲 + 出场角色卡 + 账本摘要 + 最近章结尾。设定类条目按"完整/仅名称"两档，面板可调，实时 token 预算估算，超限飘红。**可见性过滤是红线**：被隐藏或未到开放卷的条目，无论装配怎么设都不进 prompt。
6. **审校 agent**：一致性检查（对照账本与设定找矛盾，输出问题清单，逐条 diff 修复）+ 去 AI 味 pass（文风指令约束下改写）。只做改写，不做平台检测器对齐。

## 切片

每片穿过存储 / 处理 / 界面三层，独立可验证，一片一提交。

1. **作品底座**：新建作品 → 磁盘创建 md 骨架 + git init + 首次 commit；三栏 UI 骨架（左资源树 / 中会话 / 右编辑器）。验证：建作品后磁盘出现 git 仓库，删一章可从 git 恢复。
2. **模型接入**：设置页配置 rig provider（协议/key/模型）→ 中栏 agent 会话流式对话。验证：配一个 OpenAI 兼容 key 完成流式对话；key 不进渲染层。
3. **流水线状态机**：六阶段落地为状态机 + 阶段门 + 阶段导航 UI。验证：总纲未确认时进卷纲被拦截，确认后可推进，阶段可重做。
4. **设定库 + 账本 + 可见性**：设定/角色/悬念条目（md + 可见性元数据）与账本文件的结构化落地，资源树管理。验证：隐藏条目持久化，且在装配预览中不可见。
5. **diff 审阅写入**：任意产物可被 agent 修改——patch 提议 → diff 视图 → 接受（写入 + commit）/ 拒绝；含旁路会话产物回流。验证：改总纲走通提议→审阅→落盘，git log 留痕。
6. **规则装配引擎**：正文阶段按规则组装 prompt：档位、可见性过滤、token 预算条、装配预览面板。验证：切档预览变化、隐藏设定不在 prompt、预算超限飘红。
7. **正文生成 + 账本回写**：逐章 装配 → 生成 → diff 落盘 → agent 提取状态变更 → 账本 diff 回写。验证：写完一章账本自动提议更新，接受后下一章装配引用新状态。
8. **审校 + 单卷收敛**：审校 agent 出问题清单 → 逐条 diff 修复 → 复检通过。验证：走通路径全程可演示，达成交付判据。

## 非目标（MVP 明确不做）

- 云同步、账号、授权、更新服务（单机自用定位）
- 可配置工作流模板引擎（流水线写死，模板化后置）
- 知识图谱、向量 RAG 自动检索（账本 + 规则装配先顶；单卷验证不需要）
- 拆书、文风比对沉淀（DeepWrite 已验证的方向，后置）
- 平台 AI 检测器对齐、自动过审
- 导出发布格式（txt / 平台对接）、英文 fiction 特化、多人协作、移动端
